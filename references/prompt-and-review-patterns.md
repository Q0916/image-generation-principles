# 이미지 모델 입력·참조·후보 판정 패턴

이 문서는 실제 그림에 필요한 내용을 조립하기 위한 **가변적인 구조**다. 빈칸을 모두 채우는 서류가 아니며, 사용자와 공유하지 않은 별도의 승인 단계를 만들지 않는다.

## 입력 전에 정할 것

[작법 조사·체스터턴](illustration-craft-and-chesterton.md)으로 필요한 원리와 기능을 이해한 다음 아래 입력을 작성한다. 조사 출처·매뉴얼의 설명과 이번 그림의 적용 해석은 필요한 작업 메모에 두고, 모델 본문에는 선택한 도메인 개념과 그 개념을 구현할 가시적 관계·위치·강약·WHY를 전달한다. 문헌 이름이나 키워드만 쓰거나 매뉴얼 전문을 매번 붙이는 것으로 대신하지 않는다.

## 생성 전에 사용자에게 설명할 것

실제 프롬프트를 작법 지식과 체스터턴의 기능·WHY에 맞춰 먼저 구성한 다음, 도구 호출 **전에** 사용자에게 어떤 그림으로 생성할지 설명한다. 사용자 설명과 실제 모델 입력이 다른 방향을 가리키지 않게 한다. 이 순서와 적용 범위는 [SKILL.md의 생성 전 설명](../SKILL.md#5-1-작법으로-프롬프트를-개선하고-사용자에게-명시한-뒤-생성한다)을 따른다.

설명은 사용자가 원하는 매력 → 이번에 선택한 시각적 수단 → 기대하는 눈에 보이는 효과를 연결한다. 사용자의 전문성은 현재 대화에서 파악한 만큼 맞추고, 모르면 익숙한 말부터 쓴다. 사용자를 두 집단으로 고정하거나 지식 수준을 판정하는 별도 질문은 하지 않는다. 아래 대화는 설명 방식을 보여주는 예시이며, 특정 자세·배경·명암 처리를 모든 그림의 기본 처방으로 삼지 않는다.

### 예시 A: 작법 용어 없이 레퍼런스와 “고퀄”을 요청한 경우

상황: 밝은 머리색, 귀와 꼬리, 머리 위 장식, 유카타 차림의 캐릭터 레퍼런스가 첨부됐다. 이 설명은 대화 예시를 위한 가정이며 원본 이미지를 이 패키지에 포함했다는 뜻은 아니다.

사용자:

> 이 레퍼런스로 고퀄 이미지 만들어줘.

에이전트의 최소 질문:

> 두 가지만 알려줘. 이 캐릭터의 어떤 모습을 보고 싶어? 지금처럼 유카타를 입은 전신의 매력을 살릴까, 축제를 즐기는 장면이나 다른 표정·포즈를 보고 싶어?
>
> 혼자 감상할 그림이야, 누군가에게 보여줄 그림이야? 게시한다면 어디에 올릴 거야?

사용자의 답:

> 여름 축제에서 귀엽고 예쁜 모습. SNS에 올릴 거야.

에이전트는 이 답을 바탕으로 작법과 WHY를 적용한 실제 프롬프트를 먼저 구성하고, 생성 전에 다음처럼 설명한다.

> 밝은 머리색과 귀·꼬리, 머리 위 장식, 유카타의 특징은 살리고, 축제를 즐기다가 이쪽을 돌아보는 모습으로 만들게. 몸은 한쪽에 편하게 무게를 싣고 소매와 옷주름도 그 움직임을 따라가게 해서 자연스럽게 잡을 거야. 손과 소품도 편하게 들고 있는 관계로 정리할게.
>
> SNS에서 작게 봐도 표정이 먼저 눈에 들어오도록 얼굴 주변의 빛과 색 차이를 잡을게. 축제 배경의 볼거리를 살리면서 인물과 어울리도록 빛과 묘사의 강약을 조절해서 생성할게.

여기서 “고퀄”만으로 새 포즈·축제 배경·SNS 게시를 확정하지 않는다. 그 선택은 사용자의 답을 받은 뒤 내린 것이다. 레퍼런스가 정체성·의상·화풍·구도 중 무엇을 제공하는지도 실제 입력에 구별해 전달한다.

### 예시 B: 사용자가 작법 용어로 주문한 경우

사용자:

> 이 캐릭터로 여름 축제 일러스트. 3/4뷰에 콘트라포스토를 살리고, 캐릭터와 배경의 명도 그룹을 분리해줘. 얼굴 중심으로 에지 컨트롤하고.

원하는 볼거리와 시각적 처방은 받았지만 감상·게시 맥락은 빠져 있다. 전문적인 주문이라는 이유로 그것까지 안다고 가정하지 않고 빠진 항목만 묻는다.

> 혼자 감상할 그림이야, 누군가에게 보여줄 그림이야? 게시한다면 어디에 올릴 거야?

사용자의 답:

> SNS에 올릴 거야.

에이전트는 용어를 실제 작화 관계로 풀어 프롬프트에 반영하고, 사용자에게는 익숙한 용어와 구체적인 적용을 연결해 설명한다.

> 3/4뷰에서 체중을 받는 다리와 골반·어깨의 기울기가 이어지도록 잡고, 유카타 아래에서도 콘트라포스토가 읽히게 소매와 옷주름을 정리할게. SNS 축소 감상에 맞춰 캐릭터와 축제 배경의 큰 명도 그룹을 나누고, 얼굴 주변은 선명하게, 주변부는 부드럽게 에지를 조절해 시선을 모으겠어. 밝은 머리카락과 피부가 한 덩어리로 뭉개지지 않도록 중간 명암도 확보해서 생성할게.

사용자가 쓴 용어를 단순히 되풀이하거나 매번 입문 강의로 바꾸지 않는다. **어느 부위·관계에 어떤 강약으로 적용하고 어떤 효과를 기대하는지** 설명한다. 용어의 의도가 모호하거나 서로 충돌하면 필요한 부분만 질문한다. 두 예시 모두 설명에 대응하는 실제 프롬프트를 먼저 준비하고, 설명을 보낸 다음 요청된 범위에서 생성한다.

“전문 기법을 활용하겠습니다”라는 선언이나 완성 후 해설만으로는 사전 설명이 되지 않는다. 한편 쉬운 사용자 설명만을 모델용 프롬프트로 사용해 필요한 WHY·관계·참조 정보를 잃는 일이 없도록 한다. 매번 승인 답변을 요구하는 절차는 아니며, 핵심 불확실성은 생성 전에 질문으로 해결한다.

## 1. 모델용 입력의 구조

```text
IMAGE INTENT / WHY
- 내가 보여주고 싶은 것:
- 제3자가 이 그림에서 보고 싶어할 것:
- 상업적으로 보여줘야 할 매력:
- 이번 이미지를 볼 때 먼저 읽힐 것 → 머물 것 → 느낄 것:

WHAT IS HAPPENING / CONTEXT
- 장면·인물 상태·사건/감정의 이유:
- 누가 누구에게 무엇을 하며, 무엇이 보여야 하나:
- 화면에 그리지는 않지만 해석에 필요한 문맥:

VISIBLE CONTENT / REFERENCE ROLES
- 실제 보이는 인물·물체·상태(필요한 것만):
- 참조 1: identity / outfit / style / composition / setting ... 중 정확한 역할
- 참조 2: ...
- 보일 면·글자·행동·접촉·색·소유 관계:

VISUAL DIRECTION
- 선택한 작법 개념과 이번 그림에서 살릴 기능:
- 그 기능을 구현할 구체적인 관계·위치·강약과 WHY:
- 실루엣/표정/시선의 중심:
- 구도·관찰 관계·초점의 이유:
- 기본 그림체(선·색·그림자·형태):
- 특징적인 시각 언어(이번에 쓰는 곳/조용한 곳):
- 배경 역할·색/디테일의 우선순위:

MUST KEEP / CREATIVE FREEDOM
- 의미를 바꾸므로 유지할 선택:
- 의미를 유지하며 모델이 결정할 표현:

TEXT IF ANY
- 정확한 문자열 / 소유자·채널 / 읽는 순서·상대 위치:

OUTPUT
- 이미지 용도·형식·비율·텍스트 가독성·필수 조건:
```

원문 WHY/행동/관계가 복잡하면 충분히 길게 쓴다. 간단한 일러스트는 필요한 줄만 사용한다. `must keep`이 작은 구도를 강제하는 것과 `creative freedom`으로 핵심을 비우는 것은 둘 다 실패 원인이다.

## 2. 스타일-only 실험을 위한 구체적 역할 지도

```text
REFERENCE ROLES
1. [실제로 첨부한 인물 정본] — identity / current outfit ONLY.
   이 참조의 포즈·카메라·배경은 새 이미지의 구도 계약이 아니다.
2. [실제로 첨부한 별도의 스타일 예시] — style ONLY.
   그림 속 인물의 얼굴·의상·포즈는 옮기지 않는다.
3. [실제로 첨부한 구성 예시, 필요할 때만] — composition ONLY.
```

첨부가 없는 역할 줄은 빼고, 그 부재를 정확히 표시한다. 이미지 2장이 서로 충돌하면 어떤 특징을 어느 참조에서 가져올지 결정한다. 새로운 2D 스타일 실험 때 이전 실패 그림을 단독 style 기준으로 삼으면 실패한 표현이 고착될 수 있다. 무엇이 좋았는지 명시하고 해당 부분만 비교 자료로 사용한다.

## 3. 수정인지 변형인지

- **편집**: 사용자가 선택·제공한 원본을 기초로 지정 영역(예: 머리카락 그림자에 파편 더하기)만 고친다. 나머지 얼굴·표정·포즈·의상·구도는 가능한 한 보존한다. 도구가 이러한 국소 보존을 보장하지 못하면 그 한계를 말한다.
- **동일 설정의 새 구도**: 이전 선택본을 continuity/identity 근거로 쓰되 새로운 조명·포즈·프레이밍을 만드는 별도 생성이다. 이전 완성 이미지를 직접 덧칠하는 편집으로 취급하지 않는다.
- **새 스타일 씨드**: 특정 인물 채택 전의 화풍 탐색이라면 어떤 정체성을 잠그는지부터 정한다. style-only는 다른 인물의 정체성을 복제하는 지시가 아니다.

## 4. 출력 확인의 구분

| 종류 | 확인할 수 있는 것 | 그것만으로 확인되지 않는 것 |
|---|---|---|
| 원문·첨부 | 원문 바이트, 참조 파일, 의도한 입력 구성 | 도구 내부 모델에 모든 의미가 그대로 전달되었는가 |
| 가시적 실제 입력 | 사용자에게 드러난 prompt/수정사항 | 내부 전처리·revisedPrompt가 동일한가 |
| 도구 완료 | 요청이 수락되어 결과 파일이 생성됨 | 인물의 감정·작화 스타일·글자 품질이 맞는가 |
| 시각 검토 | 실제 보이는 표정·형태·색·질감·구도의 부합 | 단독 문구가 결과를 인과적으로 만들었는가 |
| 사용자 선택 | 그 후보를 사용하기로 골랐음 | 모든 세부 지시가 충족되었거나 재현성이 검증되었는가 |

사용자가 미술적 평가는 직접 하겠다고 하면 후보 전달과 객관 자료를 우선하고 보지 않은 이미지를 점수화하지 않는다. 검토 요청이 있으면 구체적으로 무엇이 보이고 무엇이 부족한지 분리한다.

## 5. 원인별 최소 수정

| 관찰된 문제 | 먼저 볼 층 | 바꿀 범위의 예 |
|---|---|---|
| 인물이 다른 사람 같음 | identity 참조·실제 참조 결합·현재 의상 | 참조 역할과 실제 이미지 먼저 교정, 질감 키워드는 그대로 |
| 표정은 예쁜데 이야기가 안 읽힘 | WHY·인물의 목적/상대·구도 | 행동 상대·반응 관계·가시 행동을 분명히, 관절 지정은 필요할 때만 |
| 배경만 화려하고 인물은 평범 | 세부 예산·스타일 표현 위치 | 파편/점묘를 인물 채색 경계로 보내고 배경의 경쟁 명암 줄이기 |
| 파편 대신 글리터·보케 | 질감 형태·스케일·배치 | 큰 색면→중형 다각형→미세 색점의 전이를 서술하고 국소 비교 |
| 손·소품 의미가 바뀜 | 핵심 물리 관계·참조·모델 구현 | 필수 접촉/사용 면을 잠그고 같은 오류가 계속되면 국소 수정 또는 다른 후보 선택 |
| 불필요한 텍스트/소품 추가 | 실제로 보일 정보·긍정형 목록 | 현재 화면에 필요한 대상과 정확한 텍스트만 명시, 악화가 반복되면 조건부 방어 |

부분 보완의 실효성은 새 이미지에서 확인한다. 무리하게 고정 조건을 누적해 다른 좋은 부분까지 망가뜨리지 않는다.
