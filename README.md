# IGP — Image Generation Principles

**단일 이미지·일러스트·키비주얼·포스터를 위한 작화 판단 스킬.**

**라이선스:** [CC BY-NC 4.0](LICENSE.md) + [출처 표시 면제·상업적 제작 추가 허용](ADDITIONAL_PERMISSION.md). 출처 없이 사용·수정·무료 공유할 수 있고, 유료 작업과 결과물 판매도 허용합니다. IGP 자체를 유료로 재판매하는 허락은 포함하지 않습니다.

“자연스럽게, 예쁘게, 귀엽게, 야하게, 잘 팔리게”라는 요구를 유효한 목표로 받아들이고, 원하는 매력을 작법 조사·시각 연출·참조 역할·실제 이미지 생성 입력으로 연결합니다. 성별만으로 매력 공식을 고정하지 않고 대상·취향·인물에 맞게 판단합니다.

이 스킬의 출발점은 “가설단계에서 이미지 모델에 생성협조를 요구한” 제작 방식입니다. 미술 원리와 제작 경험으로 의도를 설명하고 모델에 구현을 요청하며, 결과와 사용자 선택을 통해 개선합니다. 좋은 실사용 결과에 대한 피드백은 있지만, 개별 조항의 인과 효과나 모델 내부 기제·보편적 재현성을 증명한 이론으로 소개하지 않습니다.

**현재 확인 범위(2026-10-21): 긍정적인 실사용 피드백은 오로지 Codex에서 ima2로 이미지를 생성한 경로에서만 확인했다.** ima2는 여기서 실행 도구를 가리키며 정확한 내부 백엔드 모델 버전·전처리까지 검증했다는 뜻은 아니다. 공홈 Library에 파일을 추가하고 실제로 읽게 해 지침으로 적용할 수 있으며, Codex에서는 IGP와 ima2를 함께 사용할 수 있다. 이 사용 가능성과 모델별 효과 검증은 다르다. 다른 제공자에 대한 효과나 무작위 대조 실험으로 입증된 인과 효과는 주장하지 않는다.

## 어떤 일을 돕나요?

- 창작자가 보여주고 싶은 것, 관객이 보고 싶은 것, 상업적으로 보여줘야 할 것의 접점 찾기
- 필요한 작법을 찾아 읽고 기능·WHY를 이해한 뒤 구도·동세·비례·명암·색·질감 선택에 적용하기
- 바꾸면 의미가 달라지는 조건과 모델이 자연스럽게 풀 수 있는 표현 자유 나누기
- 정체성·현재 상태·화풍·구도 참조를 구별하고 실제 모델 입력에 문맥과 이유 전달하기
- 후보 탐색·원본 편집·사용자 선택을 이어가되 도구 완료와 창작적 성공 구별하기

체스터턴 방식으로 규칙의 이유를 먼저 회수합니다. 배경 단순화·긴 문맥·참조 분리 같은 선택을 문장 길이나 유행만으로 없애지 않고, 원래의 기능을 이해해 유지하거나 다른 수단으로 풀어냅니다. 평범한 일러스트마다 같은 조사를 반복하거나 정당화 보고서를 작성하는 절차는 아닙니다.

## 사용하기

### Codex + ima2

이 저장소의 루트가 `image-generation-principles` 스킬 폴더입니다. 사용자 스킬 설치 경로에 이 이름으로 배치하거나, 해당 환경의 스킬 설치 도구에 저장소 주소를 전달합니다. `agents/openai.yaml`은 자동 선택을 허용합니다. 각 환경의 실제 호출 방식과 사용자의 설정이 적용을 결정합니다.

```text
$image-generation-principles 를 적용해서 이 캐릭터의 여유롭고 매력적인 일러스트를 그려줘.
첨부 1은 정체성, 첨부 2는 화풍 참조로 쓰고 ima2로 생성해줘.
```

IGP가 작화 판단과 이미지 입력을 맡고, 설치된 `ima2-gen` 지침과 실제 ima2 도구가 생성·편집 실행을 맡습니다. 구상·프롬프트·검토만 요청했다면 그 범위에서 돕습니다. 이 저장소에 별도 생성 API·서버·인증은 포함하지 않습니다.

### ChatGPT Library / 일반 채팅

[`dist/image_generation_principles.md`](dist/image_generation_principles.md)는 본문과 참고자료를 한 파일로 읽는 통합본입니다. Library에 저장하거나 채팅에 첨부하고 다음처럼 지정합니다.

> 이 파일을 읽고 이번 그림에 스킬처럼 적용해줘.

파일을 저장한 것과 해당 대화가 실제로 읽고 적용한 것은 구별합니다. 자동 설치·자동 호출은 보장하지 않습니다.

이미지 작업에서는 다음 두 정보가 명시돼 있는지 먼저 확인하고, **빠진 항목은 반드시 묻고 답을 기다립니다.**

1. “네가 이 일러스트에서 보고 싶은 건 뭐야?”
2. “나만 볼 그림이야, 누군가에게 보여줄 그림이야? 게시한다면 어디에 올릴 거야?”

둘 다 빠졌다면 한 번에 함께 묻고, 이미 받은 답은 다시 묻지 않습니다. 원하는 볼거리와 개인 감상·전달·게시 맥락을 실제 구상과 생성 입력에 반영합니다. 단순한 저장소 읽기·설치·요약에는 이 질문을 요구하지 않습니다. 사용자가 명시적으로 질문 없이 진행하라고 하면 그 지시를 따릅니다.

답을 바탕으로 에이전트가 작법 지식과 체스터턴의 울타리(기존 선택의 기능과 WHY 보존)를 적용해 실제 프롬프트를 먼저 정리합니다. 그런 다음 **사용자에게 익숙한 말로 어떤 그림을 왜 그렇게 만들지 명시한 뒤 생성합니다.** 작법에 익숙한 사용자에게는 그 지식 수준에 맞춰 설명합니다. 생성에는 시간과 비용이 들기 때문에 의도가 어긋난 헛수고를 줄이기 위한 순서입니다. 이미 요청한 생성에 매번 재승인을 요구하는 절차는 아닙니다.
